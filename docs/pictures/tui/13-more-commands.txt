keel's rules for scratch (saved in .keel/config.yml and .keel/rules/):

Engines:
  claude: every edit, shell command, read and MCP call is checked before it runs
  opencode: every edit, shell command, read and MCP call is checked before it runs
  codex: every edit, shell command, read and MCP call is checked before it runs
  copilot: shell commands of git, gh, the package managers and file printers are checked before they
 run; file edits are checked after each step (the diff guard puts a refused file back)
  api: every edit, shell command, read and MCP call is checked before it runs

Always on:
  phase-matrix: Each phase lets agents change only some kinds of files: tests in RED, code in GREEN,
 nothing in a review. (in a flow)
  env-files: .env files hold secrets: agents never read, print or change them (setup may write the
env file). (always)
  keel-rules-files: Agents never change .keel/config.yml or .keel/rules/: an agent may not change
its own rules. (always)
  keel-keys: keel's own keys (its internal token and the sign-in key) are never read, printed,
changed or sent by an agent: with them anyone could act as keel or as you. (always)
  migrations-immutable: An existing database migration is never changed; a new migration file is
added instead. (always)
  force-push: git push --force and git push -f are refused: they can delete other people's work.
(always)
  no-verify: --no-verify is refused: it skips the checks keel relies on. (always)
  commit-in-flow: In a flow keel makes every commit after its checks; an agent's own git commit is
refused. (in a flow)
  history-rewrite: git reset --hard and git rebase -i are refused in a flow: they throw work away.
(in a flow)
  secrets-at-write: An edit that adds what looks like a secret (a key, a token, a password) is
refused before it is written. (always)
  disabled-tests: A test may not be switched off: skip, only, @Disabled, xit and the like are
refused in test files. (always)

keel's rules you can switch off:
  generated: Generated files are not edited by hand: change the source and run the generator.
(always)
  read-build-output: Build output (build/, node_modules/, target/ ...) is not read: it wastes the
agent's context. (always)
  skip-test-flags: -x test and -x check are refused: they skip the tests in a Gradle build. (always)
  new-dependency: Installing a new package is a decision for the spec and a gate, not for an agent.
(in a flow)
  read-twice: Reading the same unchanged file twice in one step is refused: the agent already has
it. (always)
  big-file-read: A big file (more lines than read_guard_max_lines) is read in parts, with offset and
 limit. (always)
  push-gate: An agent's git push or gh pr create is refused while keel's push blockers say the
branch is not ready. (always)
  mcp-writes: In a flow, an MCP tool that can change things runs only when mcp.allow names it. (in a
 flow)
