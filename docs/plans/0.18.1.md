# keel v2 0.18.1 — keel's local api proves every caller

Branch `claude/security-0181`, on v0.18.0 (`9797300`). Plan: `docs/plans/agent-clients.md` section 0 (on branch
`claude/feat-agent-clients-ddbaa4`). Contract: `docs/CONTRACT.md`, "v0.18.1: keel's local api proves every caller".

Until 0.18.0 a request without the MCP headers passed with no check: any program on the computer, or a web page
through the browser, could approve a gate, start a flow or delete a secret.

```
 browser          a cookie set by a one-time link keel2 opens (keel2 open, start), + X-Keel-Web and keel's own Origin
 keel TUI         Authorization: Bearer <web key> (keel2 tui passes the key's file)
 xal's plugin     Authorization: Bearer <web key> (KEEL_WEB_KEY, else keel2 auth key); its MCP path: level tokens
 keel2 mcp, Claude Code, OpenCode, Codex   the MCP level token (an HMAC of the internal token)
 engine, keel2, scripts, e2e               keel's internal token
 keel's agents    a read MCP token only; the never-off rule keel-keys keeps them away from every key
 anything else    401 "keel needs you to sign in" (the web shows one sign-in screen)
```

Also: a Host allow-list (DNS rebinding), no CORS answer ever, `/internal/events` refuses everyone when the internal
token is empty, `keel2 auth reset` and `keel2 auth key`, `keel2 open --print | --dev`.
